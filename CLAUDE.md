# CLAUDE.md

Read this before touching anything. It is short on purpose. The long versions are in
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) and [docs/PERF.md](docs/PERF.md).

## What this is

ROVERKRAFT — a lunar rover survey game that runs in a browser tab and installs on a phone.
WebGL2, a vendored copy of three.js, plain ES modules, no build step, no npm dependencies,
no asset files. Everything you see and hear is generated by code at load.

A fork of `winchxyz/moon-rover` (REGOLITH, MIT). Almost every note in this file and in
ARCHITECTURE.md is upstream's and is still true. What the fork changes is the design
target: **the phone is the primary platform, not the fallback.** Upstream cuts seven
instruments on a phone and nothing brings them back; here they are re-parented into a
status tray, the frame rate is capped so the SoC never gets hot enough to throttle, and
the interface is coded by function class rather than decorated.

`src/` is ~8,150 lines. The valuable part is not the rendering — it is that the physics and
the pixels are forced to agree.

## The one contract that holds the game together

**The wheels and the shader read the same height field.** The GPU never re-derives a height;
it samples the baked field the CPU owns, and the CPU bilinear filter in `terrain.js` is
written to match GL's. If the two ever disagree where the rover is standing, it floats or
sinks, and no amount of tuning fixes it.

Anything that changes how height is computed must change it on both sides in the same commit.

## Non-negotiables

1. **Never replace a uniform wrapper object — only mutate `.value`.** Every clipmap ring
   shares the same wrapper objects (`buildClipmap` does `Object.assign`), and `Dust` holds
   `uSunDir` directly. Swapping a wrapper silently unwires them.

2. **Run `node --check` on every file you changed before you say it works.** The browser
   reports a syntax error as "missing )" with no file, and you will lose an hour.

3. **Verify in the running game, not by reasoning.** `window.REGOLITH` exposes the live app
   and `REGOLITH.tick(dt)` advances one frame by hand. Claims about behaviour that were not
   observed are not findings.

4. **Measure before and after.** Put the two numbers in the commit message. "Feels better"
   is not a result.

5. **Never write an absolute you have not checked.** "no X", "every Y", "always", "never" —
   the README has been wrong about this class of claim three times. Check, then write.

6. **`--s` resolves only inside `.hud`, `#touch` and `.tray`.** A `calc(N * var(--s))`
   anywhere else is an invalid value, and CSS drops the whole declaration — the element
   silently falls back to browser defaults. Any new subtree that carries instrument
   dimensions has to redeclare `--u` and `--s`, and the status tray does.

7. **The soil map is nearest-sampled on both sides.** `terrain.soilAt()` and the shader's
   `uSoil` lookup must read the same cell; a filtered soil index is a soil that does not
   exist. It carries no height, so it is outside the physics/pixels contract entirely —
   only the tint's lookup position is jittered, and by less than one texel.

8. **`sw.js` has no crawler.** Adding a source file means adding it to the shell list by
   hand. A missed entry does not break the game — the runtime handler still fetches and
   caches it — but it costs the first offline load, and a cold install with the tab
   already offline fails outright.

9. **Missions are data.** `lore.js` holds the text AND what each objective watches for;
   `gameplay.js` holds the machinery. Do not add a `missionIdx` comparison — that is
   exactly what the `reveals` / `grants` / `watch` fields exist to replace, and inserting
   a mission in the middle used to point the deep-drill gate at the wrong one.

10. **Bump `KEY` in `save.js`** in the same commit as any change to anomaly generation,
    the terrain its filters read, or the mission list. Anomaly state is a bare positional
    array with no id and no coordinates, and the key is the only version field there is.

## Running it

```bash
npm start
```

Then <http://localhost:5173>. Any static server works; it must be HTTP, not `file://`,
because it uses ES modules. Node 18+.

`node server.js 5173 --shots` adds a `POST /__shot` endpoint that writes frames into
`.shots/` — used to capture screenshots while testing. Off by default.

`window.ROVERKRAFT` is the debug handle; `window.REGOLITH` is kept as an alias so every
note written against upstream still works. `ROVERKRAFT.applyLevers()` pushes a settings
change through the engine the way the panel does.

## Where things are

| | |
|---|---|
| `src/core/` | engine, input, audio, rng, save, perf |
| `src/world/` | terrain, soil, props, sky, dust, textures |
| `src/game/` | rover, gameplay, lore, camera |
| `src/ui/` | hud, theme, styles |
| `src/main.js` | boot, menus, settings, the frame loop, install |
| `sw.js` · `manifest.webmanifest` | the offline shell |

The frame loop in `main.js` is the thing to read first. Order of operations there matters
and is documented in ARCHITECTURE.md.

## Docs

[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — how the systems work and the invariants
between them. Read the section for whatever you are about to touch. It is written to be read
in pieces, not front to back.

[docs/PERF.md](docs/PERF.md) — how to measure the phone, and what counts as a pass. The
short version: a flat p95 at minute ten, not a high number at minute one. Any performance
claim about this fork that was not taken from a trace on a real device is a guess.

Development happens in a private repository, which carries three more files under `docs/`:
`RULES.md` (roles, task specs, acceptance, commits), `BOARD.md` (what is being worked on) and
`DECISIONS.md` (settled questions, so nobody re-opens one by accident). **If those files are
present, read `RULES.md` before starting work** — it defines how a task is picked up and what
counts as done. If they are not, you are in the public release repository.
